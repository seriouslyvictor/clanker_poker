<objective>
Wire the backend demand gate and game_status SSE event. The game loop stops auto-looping and instead waits for a viewer-triggered asyncio.Event. A new REST endpoint (POST /api/game/start) validates viewer presence and fires the event. A new SSE event type (game_status) broadcasts idle/running state to all clients on connect and on session transitions. Redis stores the last session result for late joiners.

Purpose: Establishes the server-side contract that prevents the game running without a viewer, and gives the frontend the state signal it needs to route between idle and live views.

Output: A demand-gated backend — game only runs after POST /api/game/start — with game_status events flowing through SSE to all clients.
</objective>

```python
async def publish_game_status(
    broker: "EventBroker",
    redis_client: redis.Redis,
    running: bool,
) -> None:
    """
    Broadcast game_status event directly to all connected clients via broker.broadcast().
    Does NOT use Redis pub/sub — game_status is always generated by the local process.
    When running=False, reads game:last_result from Redis to include lastWinner.
    """
    if running:
        payload = json.dumps({"running": True})
    else:
        last_result_raw = await redis_client.get(GAME_LAST_RESULT_KEY)
        last_winner = None
        if last_result_raw:
            data = json.loads(
                last_result_raw.decode("utf-8") if isinstance(last_result_raw, bytes)
                else last_result_raw
            )
            last_winner = {
                "name": data["winnerName"],
                "org": data["winnerOrg"],
                "hand": data["winnerHand"],
            }
        payload = json.dumps({"running": False, "lastWinner": last_winner})

    envelope = json.dumps({"event": "game_status", "data": payload})
    await broker.broadcast(envelope)
```

```python
            logger.info("Budget: %s", budget.summary())

            session_winner = max(session.players, key=lambda p: p.chips)
            last_hand = completed_hands[-1] if completed_hands else None
            winner_hand_name = last_hand.winner_hand if last_hand and last_hand.winner_hand else "last standing"
```

**backend/app/api/game.py — NEW file:**

```python
"""
game.py — POST /api/game/start demand-gate endpoint.

D-05: Checks game_running flag and viewer_count before firing asyncio.Event.
D-08: Returns 409 if game already running, 503 if no viewers, 200 on success.
"""
from fastapi import APIRouter, Request, HTTPException

router = APIRouter()


@router.post("/api/game/start")
async def start_game(request: Request):
    """
    Trigger a new game session. Enforces two server-side guards:
    1. No game currently running (409 if violated)
    2. At least one viewer connected (503 if violated)

    Sets app.state.start_event — the asyncio.Event that game_loop.py awaits.
    Returns {"started": True} on success.
    The game_status { running: true } SSE event will arrive separately via SSE channel.
    """
    if request.app.state.game_running:
        raise HTTPException(status_code=409, detail="Game already running")
    if request.app.state.broker.viewer_count < 1:
        raise HTTPException(status_code=503, detail="No viewers connected")

    request.app.state.start_event.set()
    return {"started": True}
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Denial of Service | POST /api/game/start | accept | No rate limiting required v1 — only consequence of spam is 409 after first success; game_running flag prevents double-start. Game loop holds the event loop slot. |
| T-06-02 | Spoofing | POST /api/game/start | accept | No auth in v1 (locked decision — anonymous viewers). Any visitor can trigger a game, which is intentional per VIEWER-02. |
| T-06-03 | Tampering | game:last_result Redis key | accept | Redis is local/Docker, not exposed to internet. Key is read-only by SSE clients. Worst-case tampering: incorrect last winner display, no game integrity impact. |
| T-06-04 | Information Disclosure | game_status SSE event | accept | Payload contains only: game running state and last winner (public information). No PII, no credentials. |
| T-06-05 | Elevation of Privilege | POST /api/game/start | mitigate | `app.state.game_running` flag check (409) prevents a second viewer from starting a second session. Flag is set before broadcast (ordering enforced in Task 2 — Pitfall 2). |
| T-06-06 | Denial of Service | asyncio.Event demand gate | mitigate | `start_event.set()` on already-set Event is idempotent (Python asyncio stdlib behavior). CancelledError re-raise preserved (Task 2) ensures clean shutdown. |
</threat_model>
