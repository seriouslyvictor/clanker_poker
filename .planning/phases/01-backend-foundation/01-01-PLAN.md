```python
from functools import lru_cache
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    # Player model config — any LiteLLM-compatible model strings
    # LiteLLM reads OPENAI_API_KEY, ANTHROPIC_API_KEY etc. directly from os.environ
    player_models: list[str] = [
        "openai/gpt-4o",
        "anthropic/claude-3-5-haiku-20241022",
        "gemini/gemini-2.0-flash",
        "ollama_chat/llama3",
    ]
    llm_timeout_seconds: int = 8
    cors_origins: list[str] = ["http://localhost:3000"]

    model_config = SettingsConfigDict(env_file=".env", extra="ignore")


@lru_cache
def get_settings() -> Settings:
    return Settings()
```
Key: NO provider-specific key fields (openai_api_key, anthropic_api_key, etc.).
LiteLLM reads those from os.environ automatically — no pydantic-settings wrapper needed.
Adding a new provider requires only updating PLAYER_MODELS in .env, not modifying any Python code.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → process | Provider API keys cross from .env file (or OS env) into Python process memory at startup via LiteLLM's os.environ reads |
| source code → git | Any file committed to git is permanently in history even if later deleted |
| config.py → logs | Settings object fields could be accidentally printed/logged; player_models is safe to log (no secrets), but env vars read by LiteLLM are not |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `.env` file | mitigate | Add `backend/.env` to `.gitignore` immediately in Task 1 before any other files are created. Only `.env.example` (with empty values) is committed. |
| T-01-02 | Information Disclosure | `backend/app/config.py` | mitigate | Settings class contains no provider API key fields — LiteLLM reads them from os.environ directly. `extra="ignore"` prevents unknown env vars from surfacing in Settings. Never log os.environ values that may contain secrets. |
| T-01-03 | Information Disclosure | `backend/app/main.py` logs | accept | Phase 1 has no request logging. FastAPI default logs do not include request bodies or env vars. Low risk in development-only server. |
| T-01-04 | Tampering | `GET /health` endpoint | accept | Health endpoint returns static string. No user input accepted. No state exposed. Unauthenticated access is intentional — this is a liveness probe, not a sensitive endpoint. |
| T-01-05 | Information Disclosure | `uv.lock` in git | accept | `uv.lock` records dependency versions (public info) and hashes. No secrets. Committing lockfile is standard practice and required by D-02. |
</threat_model>
