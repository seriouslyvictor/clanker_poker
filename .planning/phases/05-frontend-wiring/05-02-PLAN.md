<objective>
Three backend fixes for Phase 5:
1. Update FastAPI CORS to allow the Vite dev server origin (http://localhost:5173).
2. Add `retry: 3000` to SSE events so the browser reconnects within 3 seconds — making the STREAM-04 reconnect SLA verifiable.
3. Store the current reasoning buffer in Redis and send it as a snapshot on client connect — so a reconnecting client recovers reasoning state, not just table state.

Purpose: Without these fixes, CORS blocks Vite requests, the browser reconnect timing is unspecified, and reasoning text is permanently lost on any network blip.

Output: Updated `config.py`, `.env.example`, `stream.py`, and `publisher.py` with all three fixes applied.
</objective>

From backend/app/broadcast/publisher.py (current state):
```python
CHANNEL = "game:state"
SNAPSHOT_KEY = "game:state:last"
SNAPSHOT_TTL = 3600
REASONING_CHANNEL = "game:reasoning"

async def publish(redis_client, state: GameState) -> None:
    payload = state.model_dump_json(by_alias=True)
    await redis_client.set(SNAPSHOT_KEY, payload, ex=SNAPSHOT_TTL)
    await redis_client.publish(CHANNEL, payload)

async def publish_reasoning(redis_client, player_id, phase, delta, done) -> None:
    payload = json.dumps({"playerId": player_id, "phase": phase, "delta": delta, "done": done})
    await redis_client.publish(REASONING_CHANNEL, payload)
```

REASONING SNAPSHOT DESIGN:
- Add `REASONING_SNAPSHOT_KEY = "game:reasoning:current"` — a Redis list of reasoning delta JSON strings.
- In `publish()` (called at each phase transition): clear the reasoning list with `await redis_client.delete(REASONING_SNAPSHOT_KEY)` — new hand, new reasoning accumulation.
- In `publish_reasoning()`: append each delta to the list with `await redis_client.rpush(REASONING_SNAPSHOT_KEY, payload)` and set TTL with `await redis_client.expire(REASONING_SNAPSHOT_KEY, SNAPSHOT_TTL)`.
- In `stream.py` on connect: read the list with `await redis_client.lrange(REASONING_SNAPSHOT_KEY, 0, -1)` and emit it as a single `reasoning_snapshot` event containing the full list of deltas as a JSON array.
- Frontend (Plan 03) handles `reasoning_snapshot` by replaying all deltas in order to rebuild reasoning state.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → FastAPI | CORS headers gate which origins can make credentialed requests |
| config.py → main.py | cors_origins default is the code-level fallback; CORS_ORIGINS env var overrides for production |
| Redis → SSE stream | Reasoning snapshot from Redis is serialized as JSON and sent verbatim — treated as trusted internal data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Elevation of Privilege | CORS misconfiguration | mitigate | Enumerate exact origins in cors_origins list; never use wildcard "*" with allow_credentials=True — CORS spec rejects this and FastAPI will raise a startup warning |
| T-05-02-02 | Information Disclosure | Production origin hardcoded in config | mitigate | Production origin must be set via CORS_ORIGINS env var; .env.example documents the pattern; .env is gitignored |
| T-05-02-03 | Tampering | CORS_ORIGINS env var injection | accept | Environment is controlled (VPS); attacker controlling env vars already has full server access |
| T-05-02-04 | Tampering | Reasoning snapshot in Redis manipulated | accept | Redis is localhost-only (no external exposure); attacker with Redis access already has full server compromise |
| T-05-02-05 | Denial of Service | REASONING_SNAPSHOT_KEY unbounded growth | mitigate | `expire(REASONING_SNAPSHOT_KEY, SNAPSHOT_TTL)` called on every rpush; key auto-expires after 1h; phase transitions call delete() to reset |
</threat_model>
