# Summary: Rich Logging + LLM Budget

## What was done

**logging_config.py** (new): `setup_logging()` configures `RichHandler(markup=True, rich_tracebacks=True)`. Suppresses `httpx`, `httpcore`, `uvicorn.access`, `litellm` to WARNING — only game/LLM events show at INFO.

**main.py**: `setup_logging()` called first in the lifespan before any other startup.

**game_loop.py**: Session start prints `═══ NEW SESSION ═══` banner with each player's name, archetype, chip count, and model string. Session end prints final chip counts and budget summary.

**session.py**: Hand start logs `── Hand N/M ──` with dealer name and all stacks. Hand end logs winner, hand name (or "last standing"), and updated stacks.

**game.py**: Phase-start logs for PRE-FLOP (with blinds), FLOP/TURN/RIVER (with board cards and pot), SHOWDOWN (pot). Per-action log after every player decision: name, action type, amount, chips remaining — color-coded (raise=green, fold=yellow, call/check=white).

**decision.py**: `max_tokens` raised from 300 → 5000. LLM call logs use cyan markup (`⚡ model → player`), response log shows char count, parsed action log shows action in context-appropriate color.

**prompt.py**: Removed dead `MAX_SYSTEM_TOKENS = 150` and `MAX_USER_TOKENS = 250` constants — never enforced, just misleading.

## Key decisions
- Conciseness enforced at prompt level ("1-2 sentences"), not via hard token cap
- `litellm` logger suppressed to WARNING — it emits verbose per-call debug noise that drowns game events
- Rich markup used inline in log messages rather than custom Formatter subclass — simpler and sufficient
